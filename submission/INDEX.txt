1.  ROC ON THE DATASETS - LFW vs MLFW, SIDE BY SIDE
==============================================================================
  results/dataset_roc_lfw_vs_mlfw.png    both datasets on one axis
  results/dataset_roc_metrics.json       every number behind the plot
  results/mlfw_roc.png                   MLFW official 6,000-pair protocol
  results/mlfw_metrics.json
  dataset_roc.py, masked_eval.py         code that produced them

  One checkpoint, one threshold, one pairing protocol, two datasets, so the
  difference measured is the mask and nothing else. Both datasets go through
  the same YuNet + landmark alignment - MLFW is read from its origin/ images
  rather than its supplied 112px crops, so preprocessing is not a confound.

                        ROC-AUC     EER      TAR @ FAR 1%
    LFW  (unmasked)      0.9587    9.61%        72.76%
    MLFW (masked)        0.8388   24.58%        35.36%
    cost of the mask    -0.1199   +14.97pp     -37.40pp

  MLFW is restricted to the 1,779 of its 2,996 identities absent from the
  training split. The other 40.3% overlap, because MLFW derives from CALFW
  which derives from LFW. That overlap was found and excluded before any
  MLFW number was produced.

  The right-hand panel scores EVERY pair rather than a 5,000-pair sample -
  523,104 impostor pairs for LFW, 16,668,556 for MLFW - so the low-FAR
  region is genuinely resolved instead of being a staircase. Curves are
  drawn solid where at least 50 impostor pairs support the point and dotted
  below that, because the far tail is an extrapolation, not a measurement.

  Mask augmentation was tested as a fix - synthesise masks during training so
  the model must work from eyes, brow and outline. It works on masked faces
  (+7.96 pp TAR@FAR=1%, -3.57 pp EER) but costs unmasked accuracy (-4.00 pp
  TAR@FAR=1%, -4.50 pp Rank-1), so the unmasked-optimised model ships. Full
  numbers in README.md under "Mask augmentation - measured, and not adopted";
  the code ships behind a --mask-p flag.

  On MLFW's own official 6,000-pair protocol the model scores AUC 0.5537,
  near chance. That protocol is adversarial by construction - same identity
  in different masks, different identities in the same mask, layered on
  CALFW's cross-age gap - and this model never saw a masked face while
  training. Filtering the leaked identities barely moves it (0.5465), which
  says the difficulty is the protocol, not the overlap.

6.  CROPPING, ALIGNMENT AND FACE LANDMARKS
==============================================================================
  landmarks.json                         5 points for all 9,164 images
  dataset_preparation.py                 detect -> landmarks -> align -> crop

  YuNet detects the face and returns five landmarks: both eye centres, the
  nose tip and both mouth corners. A similarity transform maps those onto
  the canonical ArcFace template, so the eyes land on the same pixels in
  every image and the network stops spending capacity on pose.

  Measured effect of adding alignment, same everything else:

    Rank-1            +8.13 pp
    TAR @ FAR 0.1%    +6.16 pp
    Open-set DIR      +8.51 pp
    ROC-AUC           -0.011

  Kept despite the AUC dip, because the strict operating points are the
  ones that decide whether a system is deployable.

  Detection succeeds on 9,164 of 9,164 images. Where YuNet returns nothing
  the pipeline can fall back to a centre crop, but the demo API disables
  that fallback deliberately so a non-face input errors instead of quietly
  returning a similarity score.

  Seed 42. Zero duplicate pairs, zero identity overlap with training - both
  asserted at generation time and recorded in the stats files.

  Positives are drawn round-robin across identities rather than uniformly
  over possible pairs. LFW is heavily imbalanced - a few people have
  hundreds of photographs - and uniform sampling would let those few
  dominate the genuine set and quietly decide the score.

8.  SAME NAME / DIFFERENT PHOTOS   AND   DIFFERENT NAMES / SAME PERSON
==============================================================================
  results/identity_audit.txt             readable report - START HERE
  results/identity_audit.json            per-identity numbers
  identity_audit.py

  Both failure modes are detectable from the embeddings alone, with no
  extra labels required:

    A. ONE LABEL, TWO PEOPLE - a folder holding more than one individual.
       Detected as low mean similarity WITHIN that folder.
       Effect: turns genuine pairs into impostor pairs. Scores read low
       and the model is blamed for a labelling error.

    B. TWO LABELS, ONE PERSON - one individual filed under two names.
       Detected as two folder templates sitting unusually close together.
       Effect: turns impostor pairs into genuine ones. They surface as
       false accepts that are not actually the model's mistake.

  Result on the 120 test identities:

    exact duplicate images                    0
    case A flagged (coherence below 0.15)     0
    case B flagged (similarity above 0.55)    6

  All six case-B pairs were inspected and are different people - Julianne
  Moore vs Laura Linney, Bill Frist vs Dennis Kucinich, Denzel Washington
  vs John Allen Muhammad and three more. Look-alikes, not label errors. On
  LFW a close pair is often a relative; the dataset contains several
  members of the same family. A genuine duplicate identity would sit near
  the genuine-pair mean, far above 0.55.

  So zero confirmed label errors, and the reported error rates are not
  inflated by label noise. The audit runs independently of the evaluation
  and can be pointed at any split.

  How the pipeline handles each case if it did occur: pair generation
  trusts the folder, so case A costs recall and case B costs precision.
  The audit is the check that neither is silently happening.


==============================================================================
9.  SUPPORTING
==============================================================================
  results/metrics_summary.txt            every number in one plain-text file
  model.py, train.py                     architecture and training loop
  check_leakage.py                       independent audit of the no-leakage
                                         claims - run it, do not trust me
  requirements.txt, README.md

  ResNet50 -> 2048 pool -> 512-D -> L2 normalise. Trained with ArcFace
  additive angular margin plus batch-hard triplet loss. Both losses are
  implemented from scratch; no face-recognition library is used. The only
  pretrained component is the ImageNet ResNet50 backbone.

  ArcFace because the deployed system scores by cosine similarity, so
  training should optimise the same angular geometry it is judged on. The
  triplet term because the classifier is thrown away at inference, and hard
  mining works directly on the sample-to-sample distances the ROC is
  built from.

  Splits are drawn over IDENTITIES, not images, so no test person appears
  anywhere in training. check_leakage.py verifies this from the files
  rather than asking you to take it on trust.

  No frontend or demo code is included in this archive, as requested.


==============================================================================
KNOWN LIMITATIONS
==============================================================================
  Absolute accuracy sits below published LFW figures, because those train
  on external corpora orders of magnitude larger than the ~7k images used
  here. LFW skews heavily towards light-skinned adult males in frontal
  poses, so these numbers are NOT evidence of fairness across demographics.
  Open-set rejection is measured rather than assumed, and it is weak -
  28.62% DIR at 1% FPIR means most unenrolled probes are not confidently
  rejected. Masked performance is a real degradation, not a protocol
  artefact, and is the clearest target for the next iteration.
